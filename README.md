# 乐谱反复展开台

在浏览器里录入带反复记号的小节序列，后端把它展开成真实的**演奏顺序**，并并排展示原始结构与展开后的演奏带。点击任一小节可双向高亮它的全部访问，还能下载包含来源编号、全局序号与各层遍次路径的 JSON。展开后可直接在浏览器里**排练**：每个小节可标 40～240 BPM 的速度，内置 Web Audio 节拍器区分强拍弱拍，支持播放 / 暂停 / 停止与点击演奏带定位。另支持**改谱影响对照**：把当前有效谱面设为基准后，可对照修改前后两版演奏带的新增 / 删去 / 变更与起拍时间偏移。**反复次数反求**：勾选若干带左反复的小节作为待求位置，输入目标演奏编号序列，自动求出能展开成该序列的次数组合并可一键写回表格。**右反复终点纠错**：谱面无法展开时，只切换各行的右反复终点，在最多 4 处内找回通过完整校验且访问数不超过 512 的谱面。**排练记录定位**：输入逗号或换行分隔的 1～64 个排练记录编号（可含谱面外的误记编号）与 0～4 的容错数，把完整记录与演奏带的任意非空连续区间做编辑距离匹配（相同计 0，错记替换、多记删除、漏记补入各计 1），列出距离不超过容错数的前 10 个区间与总数，点击即在演奏带上高亮对应访问。**遍次排练提示单**：录入 1～32 条提示（来源小节 + 节内拍序 + 1～80 字提示语，可按反复起点限定一层或多层遍次），复用现有校验与展开后按每次访问的完整遍次路径匹配（含终点后房子的尾部路径），把命中提示落到对应访问的指定拍并按生效 BPM 累计秒数，依时间与录入顺序列出，点击即在演奏带中定位该次访问。**演奏片段摘谱**：在已展开的演奏带上按访问序号选 1～4 段互不重叠、按演奏先后排列的闭区间（合计 2～64 次访问，同一来源小节在不同遍次可重复选入），把选中的每次访问依序变成独立录入行——编号重排为 1 起连续整数、保留拍数、清除反复与房子记号，每段首行写入该次访问的生效 BPM、段内仅在速度变化时写入；复用现有校验展开与 MusicXML 结构导出生成可回读的单 part 文件，回读后的拍数与生效 BPM 逐行对应所选访问才提供下载，页面预览新行与原访问序号、来源编号、遍次路径的映射。还可从本地 **MusicXML** 文件**导入结构**（仅支持 `score-partwise` 单 part、分母为 4 的拍号、barline 反复与 1～4 编号替代结尾；忽略音符），预览确认后替换表格；也可把当前结构**导出为 MusicXML**（先复用完整校验与展开，逐行写出编号、分母为 4 的拍号、显式 BPM 与全小节休止符，嵌套反复、连续替代结尾、终点后的房子与同线双终点编码为 barline 记号），导出文件用现有导入入口即可**往返**还原同一条演奏带。选择本地 MusicXML 文件后还可在导入面板单独发起**小节时值审计**（不替换录入表格）：按各节生效拍号与正整数 divisions 用有理数拍位逐节读取 note / backup / forward，chord 继承前一同声部普通音符的起点、grace 不占时、voice 缺省为 1，同起点和弦合成一个占用区间，按声部列出缺拍、非和弦重叠与越过小节边界的拍位；缺少 divisions、非法 duration、游标移到负拍位或孤立 chord 时按源小节报错。

- 后端：FastAPI（Python 3.11）
- 前端：原生 HTML / CSS / JavaScript，无构建步骤、无外部 CDN
- 节拍音：**Web Audio API 本地合成**，不加载任何音频文件、不请求外部服务
- 展开后的访问次数上限 **512**，超过即拒绝（反求组合同样适用，超限组合不计入）

## 一条命令启动

需要 Docker 与 Docker Compose v2（`docker compose` 子命令）：

```bash
docker compose up --build
```

启动后用浏览器打开：

> **http://localhost:8000**

端口在 `docker-compose.yml` 的 `ports` 中配置，宿主机默认占用 **8000**；如需更换，改成例如 `"9000:8000"` 即可（容器内始终监听 8000）。

后台运行与停止：

```bash
docker compose up --build -d   # 后台
docker compose down            # 停止并移除容器
```

### 不用 Docker，本地直接运行

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

同样访问 http://localhost:8000 。

## 录入规则

表格中 2～64 个小节按顺序排列，每个小节包含：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| 编号 | 小节唯一标识（如 `A`、`12`、`前奏`） | 非空、≤16 字符、全表唯一 |
| 拍数 | 该小节的拍数 | 1～128 的整数 |
| 速度 | 速度标记 ♩=（BPM） | **第 1 小节必填**，40～240 的整数；其余留空沿用最近一个标记 |
| 左反复 `|:` | 该小节左边界是反复起点 | 勾选后必须填写次数 |
| 次数 | 该反复段的总演奏遍数 | 2～4 |
| 右反复 `:|` | 该小节右边界是反复终点 | — |
| 替代结尾遍次 | “房子”记号 `{1` `{2` … | 留空或 1～4 |

> 一般每行只有一个右终点；MusicXML 导入遇到**同一道物理小节线两侧各有一个 backward**（一侧是内层第 2+ 房子的次级终点，另一侧是更外层反复的主终点）时，两个终点落到同一录入行，除勾选右反复外还会带上只读的“同线双终点”归属（内部字段 `right_closes = [内层起点行, 外层起点行]`）。展开到这一边界时先完成内层房子、再闭合外层反复。手工录入无需使用该字段；单终点谱面不受影响。

### 反复段

- 左起点与右终点**成对出现且必须正确嵌套**（允许平级、嵌套，不允许交叉）。
- 一个小节可以同时带左、右标记，表示单小节反复。
- 每段反复演奏 `times` 遍；第 1 遍从起点进入，之后每次到达终点跳回起点，最后一遍继续向后。

### 替代结尾（volta / 房子）

- `volta = k` 表示该小节只在所属**最内层反复**的第 `k` 遍演奏，其他遍跳过。
- 它只能引用最内层反复的有效遍次（1～该反复的 `times`）。
- 标准用法是主终点放在 `{1` 房子末尾，之后依次给 `{2`、`{3`…… 房子：

  ```
  |: A  B  C{1 :|   D{2 :|   E{3   F
   └─ 共 3 遍 ─┘
  第 1 遍：A B C（跳回）
  第 2 遍：A B D（跳回）
  第 3 遍：A B E，然后 F
  ```

- 同一个房子可以跨多个小节，只需在房子最后一个小节上放 `:|`。
- **控制标记即使位于本遍跳过的小节上仍然生效**：例如第 2 遍跳过 `{1` 房子小节时，其末尾的 `:|` 依然驱动跳回；最终遍越过已完成的房子终点时退出该反复。
- **外层进入下一遍时，内层计数重新开始**：外层第 2 遍重新打开内层反复，内层遍数从 1 重新计数。

校验不通过时，错误条会列出全部问题并定位到具体小节（行号 + 编号），点击错误项可滚动到对应行。速度标记的校验错误码为 `TEMPO_FIRST_REQUIRED`（首节缺失）与 `TEMPO_RANGE`（超出 40～240 或非整数）。

## MusicXML 结构导入

不想手工录入时，可以从打谱软件导出的 **MusicXML** 文件直接导入结构：在“原始结构”面板点击 **导入 MusicXML**，选择本地 `.musicxml`（或 `.xml`）文件；浏览器只读取文件文本并发送给后端转换，**文件不会离开本机 / 本服务**。

导入步骤：

1. 在打谱软件（MuseScore、Dorico、Finale 等）中把谱面**导出为 MusicXML（partwise / 分部，非压缩 `.musicxml`）**；
2. 点击 **导入 MusicXML** 选择文件，后端解析结构并立即走一遍**现有完整校验与展开**；
3. 成功时面板内**预览转换后的录入行**（编号、拍数、BPM、反复与房子）及展开统计，核对无误后点 **确认替换表格**；点“取消”或转换失败都**不会改动当前表格**；
4. 确认后表格被整体替换并自动展开；旧演奏带、节拍器计划、改谱对照、反求与纠错结果**全部失效**，需重新展开 / 对照 / 反求 / 纠错。

### 支持范围

只导入**结构信息**，一切音符（音高、时值、和弦、`<backup>` / `<forward>`、多声轨等）、调号、谱号、D.S. / D.C. / coda / segno 等跳转记号均**忽略或拒绝**。具体：

| 项目 | 支持范围 |
| --- | --- |
| 文件格式 | 根元素必须是 `score-partwise`（`score-timewise` 请先在打谱软件中转成分部形式）；全曲**恰好 1 个 part** |
| 小节 | 2～64 个；以 `<measure number>` 属性作为小节编号（沿用编号唯一性等现有规则） |
| 拍号 | 只接收 `<time>` 中**分母（beat-type）为 4** 的单一拍号，以分子为拍数；**首节必有**，后续小节缺省则沿用最近一个；`senza-misura`、混合 / 交错拍号不支持 |
| 速度 | 读取小节**起始处**（首个 `<note>` 之前）的整数 BPM——`<sound tempo="…"/>`，或 `<direction>` 内单位为四分音符（`<beat-unit>quarter</beat-unit>`）的 `<metronome><per-minute>`；**首节必有**，后续留空沿用；小数、附点单位、40～240 之外一律拒绝 |
| 反复 | `<repeat direction="forward"/>` 与 `direction="backward"` 必须**成对且正确嵌套**（LIFO 配对）；backward 的 `times` 缺省 2，只接受 2～4，并写入 forward 所在起点行；同一条小节线上先闭后开（终点与下一反复起点）的写法按嵌套识别；**嵌套反复的内层 backward 与更外层第一房子 start 同线时按层级各归其主**；**同一道物理线两侧各有一个 backward（内层房子次级终点 + 外层主终点）时两个终点落到同一录入行，保留各自反复归属（`right_closes`），不合并成一个终点**；未配对记号按源小节报错 |
| 替代结尾 | `<ending>` 的 `number` 只接受**单个 1～4 的整数**（`number="1, 2"` 等组合编号不支持）；`type="start"` 到对应 `stop` / `discontinue` 所覆盖的小节整体映射为该遍次房子，含主终点之后的尾部房子与跨小节房子；同一 barline 内“旧房子 stop + 新房子 start”写法支持；同一道物理小节线两侧（右 barline 与下一小节左 barline）的记号按边界配对；编号 1 房子与本层 backward 的同线特例按“反复所属层级 + 房子实际闭合边界”判定（房子同线闭合才把线前小节计入第一房子，嵌套同线不挪动内层终点）；未闭合 / 未配对按源小节报错 |

barline 记号可位于小节的 `location="right"`（默认）或 `"left"`；**同一道物理小节线**（某小节的右 barline 与下一小节的左 barline）两侧的记号按边界配对，与写在哪一侧无关。房子起点按其所在小节线界定覆盖范围：

- **右 barline 上的 start 从下一小节起覆盖**——所在小节在线的另一侧，属于公共段，两遍（或多遍）都会演奏；
- **左 barline 上的 start 从所在小节起覆盖**（左 barline 在小节开头，与“右 barline start”是同一物理线的两种写法）；
- 唯一例外是 MusicXML 规范里**编号 1 房子 `start` 与本层 backward 同线**的写法：这道线既是房子起点又是该层反复的主终点，**线前小节**（`start` 所在的公共小节）即第一房子，主终点也落在该小节上。判定同时依据**反复所属层级与房子的实际闭合边界**：只有房子自身也在这道线闭合（`stop`/`discontinue` 就在线的同侧或另一侧，或下一遍房子在另一侧开始形成隐式闭合）、且同线的 backward 闭合的就是房子所属那一层 forward 时才算特例；`stop` / `discontinue` 与 backward 写在该线右侧（本小节右 barline）或左侧（下一小节左 barline）均可，第二房子从线后小节开始。
- **嵌套反复的同线不算特例**：当内层 backward 与**更外层**第一房子的右 barline `start` 共线、而外层房子在后面的小节才闭合时，内层终点保留在**线前小节**，外层第一房子仍从**线后小节**起覆盖、到它真正的闭合边界结束，外层 backward 的主终点落在房子末节——三者各归其位，不会把内层终点误挪到外层房子末节。
- **次级终点同样按层级与物理边界识别**：第 2+ 遍房子的 `stop` / `discontinue` 与 backward 在同一侧 barline（或另一侧闭合、且另一侧没有自己的 backward）时，该 backward 是次级终点（只置右标记、不弹反复栈）；同一条线两侧各有一个 backward 时各自只认本侧闭合记号，嵌套场景中外层 backward 不会被对侧内层房子的 `stop` 误判为次级。这套跨侧闭合 / 同线双 backward / 反复层级判定在**房子覆盖的预配对与反复落行的正式配对中共用同一份结论**——即使内层第 2+ 房子的 `stop` 写在某节右 barline、次级 backward 跨侧写在下一节左 barline，它也只会标记内层末节，不会提前弹出外层 forward。

因此官方 MusicXML / MuseScore 常见的房子写法都支持：

- MuseScore 风格：房子 `start` 在首小节左 barline、`stop` 在末小节右 barline（与 backward 同线）；
- 分离风格：编号 1 房子的 `start` 单独在公共小节右 barline、`stop` 与 backward 在房子末节右 barline，编号 2+ 房子在下一小节左 barline 开始——公共小节不会被误标进第一房子，每一遍都演奏；
- 规范同线风格：编号 1 房子的 `start` 与 backward 同在公共小节右 barline（该小节即第一房子），编号 2+ 房子在下一小节左 barline 开始；
- 跨侧同线风格：编号 1 房子的 `start` 在公共小节右 barline，而 `stop` / `discontinue` 与 backward 写在**下一小节左 barline**（同一道物理线的另一侧），编号 2+ 房子从该线开始——按物理边界识别为同一道线，线前小节归入第一房子、主反复终点落在该节，不会误判空房子；
- 嵌套同线风格：内层 backward 与更外层第一房子的右 barline `start` 恰在同一道线、外层房子到下一节之后才闭合——按反复所属层级判定，内层终点留在线前小节、外层第一房子从线后小节覆盖、外层终点落在房子末节，第二房子随后开始；同线两侧各有一个 backward 时也按层级各归其主，不再误报 `REPEAT_UNMATCHED_OPEN`。
- **同线双终点风格（嵌套反复）**：内层第二房子的 `stop` 与次级 backward 写在某节右 barline，更外层反复的主 backward 写在**下一节左 barline**——两个记号分处同一道物理小节线两侧，转换后落在**同一录入行**：该行勾选右反复，并用 `right_closes`（`[内层起点行, 外层起点行]`）保留两个终点各自的反复归属。展开时在这道边界**先完成内层第二房子（次级终点）、再闭合外层反复**；内层非最后一遍只跳回内层，外层主终点延后到内层最后一遍再次到达该边界时才闭合。无房子时同线的两个主 backward（内层 + 外层）同理。
- 嵌套 + 跨侧次级终点 + 外层同线隐式闭合：内层第二房子的 `stop` 在某节右 barline、次级 backward 跨侧写在下一节左 barline，外层反复继续；后续外层第一房子的右 barline `start` 与外层主 backward 同在一道线（backward 与下一节左 barline 的第二房子 `start` 同线，外层第一房子由它隐式闭合）——次级 backward 只标记内层末节，外层第一房子覆盖与外层主 backward 同线的线前小节，不再被预配对误判为空房子（`MUSICXML_ENDING`）。

不支持的结构（多 part、分母非 4、组合房子编号、times 超出 2～4、跳转记号、未配对反复 / 房子等）会在导入面板中**按源小节列出错误**（源小节号 + 编号），不会产生预览，也不改动表格。转换出的录入行随后直接复用现有 `/api/expand` 的校验与展开，因此任何无法通过现有规则的结构同样会被拒绝（错误即现有错误码，按转换后的行定位）。

`POST /api/import-musicxml` 请求体：

```jsonc
{ "musicxml": "<?xml version=\"1.0\"?><score-partwise>…</score-partwise>" }
```

- 成功：`200`，`{"ok": true, "result": {"measures": [ /* 录入行数组，同 /api/expand；同线双终点行额外带 right_closes */ ], "expansion": { /* /api/expand 的完整展开结果 */ }}}`；
- 结构不支持 / 未配对记号 / 现有校验展开失败：`422`，`{"ok": false, "errors": [{"code","message","index","measure"}]}`，`index` 为源小节 0 基下标（整体错误为 `null`），MusicXML 专属错误码以 `MUSICXML_` 开头（`MUSICXML_PARSE` / `MUSICXML_FORMAT` / `MUSICXML_PARTS` / `MUSICXML_MEASURE_COUNT` / `MUSICXML_TIME` / `MUSICXML_TEMPO` / `MUSICXML_ENDING` / `MUSICXML_REPEAT_UNMATCHED` / `MUSICXML_REPEAT_TIMES` / `MUSICXML_BARLINE` 等）；
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）；缺少 `musicxml`：`400`（`INVALID_REQUEST`）。

同线双终点行示例（`right_closes` 为该行右边界闭合的两个反复起点行，内层在前、外层在后）：

```jsonc
{ "number": "5", "beats": 4, "tempo": null,
  "left_repeat": false, "right_repeat": true,
  "right_closes": [2, 1],   // 内层起点在第 3 行、外层起点在第 2 行
  "times": null, "volta": 2 }
```

## MusicXML 小节时值审计

在“原始结构”面板的导入区域选择本地 `.musicxml` 文件后，除了“转换并预览”外，还可点 **审计小节时值** 单独发起时值审计：审计只读取所选文件并展示结果，**不替换录入表格**、不影响演奏带与任何已有结果；换文件或关闭面板后旧审计结果立即清除，迟到的响应不会恢复。

### 支持范围

只处理**现有结构导入支持的单 part 谱面**这一文件范围：根元素 `score-partwise`、全曲恰好 1 个 part、小节 2～64 个、拍号为分母 4 的单一拍号（首节必有、后续沿用）。审计只逐节读取 `note` / `backup` / `forward` 与 `attributes/divisions`；**速度、反复、替代结尾、调号等记号与时值无关，一律忽略**——即使它们会导致结构导入失败，也不影响审计结论。

### 游标模型

- 按各节**生效拍号**（分母为 4，分子即本小节拍数）与**正整数 divisions**（`attributes/divisions`，跨小节沿用，中途可改）解释时值，拍位一律用**有理数**表示（`p/q`，分母为 1 时只写分子）；拍位是**距小节开头的拍数偏移**（0 起，1 拍 = 1 个四分音符）。
- 每个小节按文档顺序读取：普通音符与休止符以当前游标为起点、按 `duration / divisions` 拍推进游标并占用 `[起点, 起点+时值)` 区间；`<chord/>` 音符**继承前一同声部普通音符的起点**且不推进游标，同一起点的和弦**合成一个占用区间**（终点取组内最大）；`<grace/>` 音符不占时；`<backup>` / `<forward>` 回拨 / 前移全小节唯一的游标（不分声部）；`<voice>` 缺省为 `1`。

### 审计结论

- **时值问题**按声部列出（页面展示小节、声部与拍位）：**缺拍**（`[0, 本小节拍数)` 内未被任何区间覆盖的拍位）、**非和弦重叠**（同声部不同和弦组的区间交叠）、**越过小节边界**（区间终点超出本小节拍号拍数）；全小节没有任何非 grace 音符时按默认声部整节缺拍计。
- **硬错误**按源小节报错、**不显示通过**：缺少或非正整数 divisions（`MUSICXML_AUDIT_DIVISIONS`）、非法 duration（非正整数，`MUSICXML_AUDIT_DURATION`）、`backup` 把游标移到负拍位（`MUSICXML_AUDIT_CURSOR`）、孤立 chord（前面没有同声部普通音符，`MUSICXML_AUDIT_CHORD`）；每个小节只报告第一个硬错误。文件范围不符沿用结构导入的错误码（`MUSICXML_PARSE` / `MUSICXML_FORMAT` / `MUSICXML_PARTS` / `MUSICXML_MEASURE_COUNT` / `MUSICXML_TIME` 等）。
- 无硬错误且无任何时值问题时，页面显示**审计通过**。

`POST /api/audit-musicxml` 请求体：

```jsonc
{ "musicxml": "<?xml version=\"1.0\"?><score-partwise>…</score-partwise>" }
```

- 成功：`200`，`{"ok": true, "result": {"measure_count": 2, "issue_count": 1, "issues": [{"kind": "gap", "index": 0, "measure": "1", "voice": "1", "start": "3", "end": "4", "message": "缺拍：拍位 3~4 没有任何音符或休止符。"}]}}`——`kind` 为 `gap` / `overlap` / `overflow`，`start` / `end` 为有理数拍位文本，`issues` 按小节、声部、拍位升序；
- 文件范围不符 / 硬错误：`422`，`{"ok": false, "errors": [{"code","message","index","measure"}]}`，`index` 为源小节 0 基下标（整体错误为 `null`）；
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）；缺少 `musicxml`：`400`（`INVALID_REQUEST`）。

## MusicXML 结构导出（往返）

在“原始结构”面板工具栏点击 **导出 MusicXML**，把当前录入行导出为单个 `score-partwise` 文件（单 part、`.musicxml`，全小节休止符占位、忽略一切音符内容）。浏览器只把录入行发给本机服务端生成文本，随后下载到本地；**导出不修改表格、演奏带、节拍器计划或任何已有结果**。

导出流程：

1. **先复用完整校验与展开**：与“展开演奏顺序”完全相同的行校验、括号配对、volta 归属与栈式展开（含 512 次访问上限）。谱面非法时按**原始行**列出错误（错误码、行号、编号均与展开一致），**不产生下载**，也不改动表格。
2. **生成 barline 记号**并写出文件，随后服务端立即用现有 `/api/import-musicxml` 把生成的文件**重新导入做往返自检**；只有重新导入出的录入行与展开结果和原谱逐项一致时才返回文件，否则按导出错误拒绝、不产生下载。
3. 用“**导入 MusicXML**”重新打开下载的文件、确认替换表格后，得到的谱面与原谱等价。

### 文件内容

每个小节（measure）逐行写出：

| 项目 | 写法 |
| --- | --- |
| 编号 | `<measure number="…">`（XML 特殊字符转义，重新导入后编号原样还原） |
| 拍号 | 每行都显式写 `<time><beats>拍数</beats><beat-type>4</beat-type></time>`（分母恒为 4，含中途变拍号） |
| 速度 | 仅在**原始行显式标记** BPM 的小节起始处写 `<sound tempo="整数"/>`；留空行不写、由导入沿用最近标记——显式标记位置与各次访问的生效 BPM 均与原谱一致 |
| 音符 | 全小节休止符：`<divisions>1</divisions>` 下 `<note><rest/>…<type>whole</type>`，时长等于本小节拍数 |
| 反复 | forward 在起点小节左 barline；每个反复的**主** backward 写 `times`（2～4），第 2+ 房子的次级 backward 不写 times |
| 替代结尾 | 同一所属反复、同一遍次的连续小节合并为一个房子括号：`ending type="start"` 在首小节左 barline、`type="stop"` 在末小节右 barline；连续替代结尾与**终点之后的房子**（含最末无 backward 的房子）都照此编码 |
| 同线双终点 | 内层 backward 写在该行**右** barline、外层主 backward 写在下一小节**左** barline——两个记号分处**同一道物理小节线两侧**，重新导入后还原为同一行的 `right_closes = [内层起点行, 外层起点行]`，内外层归属不变；下一小节恰好又是新的左反复起点时不冲突：该小节开头写**两道左 barline**，第一道只放外层主 backward（先闭合旧反复），第二道放新 forward（后开启新反复，房子 start 与其同组），顺序不可调换 |

### 往返一致性

下载文件经现有入口重新导入并展开后，以下各项与导出前**完全一致**（服务端往返自检逐项比对，前端也可直接核对）：

- **拍数**（每行拍号分子）与**显式 BPM**：标记行、标记值与每次访问的生效速度；
- **反复边界**：每段反复的起点行、主 / 次级终点行与次数；
- **房子遍次**：每个小节的 volta 归属与遍次，连续房子、跨小节房子与终点后的尾部房子；
- **双终点归属**：同线双终点行的 `right_closes`（内层在前、外层在后）；
- **展开演奏带**：每次访问的**来源编号、各层遍次路径（含尾部房子标记）与生效 BPM**，以及总拍数、访问数与配对摘要。

唯一一种展开器接受却无法用单 part MusicXML 表达的极端结构是**同线双终点行恰好位于全曲最后一个小节**（外层主 backward 需要下一小节左 barline，其后已无小节）；该谱面返回 `MUSICXML_EXPORT_BARLINE` 错误，**不产生下载**。同线双终点后下一小节紧接着新左反复起点（包括新起点同时是新房子首小节）的情形已可正常导出：双终点仍分置同一物理小节线两侧，新 forward 作为该小节的**第二道左 barline**独立写出，导入端按“先闭合旧反复、后开启新反复”的顺序还原，房子 start 与各终点的层级归属不丢。常规打谱软件与本工具导入支持的嵌套反复、各类房子与同线双终点写法都能正常往返。

`POST /api/export-musicxml` 请求体即小节数组（与 `/api/expand` 相同）：

- 成功：`200`，`{"ok": true, "result": {"musicxml": "<?xml …?><score-partwise>…</score-partwise>"}}`；
- 谱面非法：`422`，`{"ok": false, "errors": [{"code","message","index","measure"}]}`——错误即现有展开错误码，按**原始行**定位（结构无法编码时为 `MUSICXML_EXPORT_BARLINE` / `MUSICXML_EXPORT_ROUNDTRIP`）；
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）。

## 演奏带、双向高亮与排练节拍器

- 右侧“演奏带”按全局顺序渲染每次访问，卡片上标注全局序号、来源编号、拍数/累计拍数、各层遍次路径（如 `1/2 › 2/2` 表示外层第 1 遍中的内层第 2 遍）和**生效速度** `♩=`，颜色按嵌套深度区分。
- 遍次分组之间有虚线分隔与文字标签。
- **点击左侧任一小节行（或卡片左上角的 ⇄ 按钮）**，该来源小节的表格行以及演奏带上它的**全部访问**会同时高亮；再次点击取消。

### 速度标记

- 速度设在**原始小节**上：第 1 小节必填，后续小节留空则沿用最近一个显式标记。
- 展开后的**每次访问按来源小节取得生效速度**——因此反复跳回的小节即使中间出现过别的速度，回来后仍按它自己的来源小节速度演奏。
- 卡片上的 `♩=` 默认显示生效值；当某次访问的速度与上一次不同（新标记生效）时用描边样式标出，悬停可见“本小节标记 / 沿用前一标记”。

### 排练节拍器

演奏带上方控制条提供 **▶ 播放 / ⏸ 暂停 / ⏹ 停止**，状态文字实时显示当前小节、拍序与 BPM。

- **本地合成 + 前瞻调度**：节拍音全部由 Web Audio API 的 `OscillatorNode` 合成（强拍 1568 Hz 带高八度泛音、更响更长；其余拍 1046 Hz），调度器每 25 ms 把未来约 0.12 s 的节拍按音频时钟提前排队，避免定时器抖动。
- **强拍区分**：每小节第 1 拍是强拍（卡片上第一个拍点更大），播放时当前拍点亮色放大，当前访问卡片与左侧来源行同步高亮，并在临近离屏时自动跟随滚动。拍数较多（>12）的卡片改用“第 x/N 拍”文字指示。
- **暂停记忆**：暂停时取消所有已排队但尚未响起的音源，并记住**下一未响节拍**（卡片以琥珀色标出）；恢复后精确从该拍继续，不会补响暂停期间的拍。
- **点击演奏带定位**：点击任一访问卡片即跳到该次访问的**强拍**（暂停态等待播放）；定位会取消此前已排队的音源，再按播放即从此处开始。
- **停止**：回到全曲开头并清除高亮，取消全部已排队音源。
- **计划失效**：小节（增删、反复记号等结构）、拍数或 BPM 一旦改动，**旧播放计划立即失效**——演奏带变灰、节拍器按钮禁用并出现“重新展开”提示；重新展开成功后才能再次播放。

> 浏览器要求用户手势后才能启动音频：首次点击“播放”即会创建/恢复 `AudioContext`，无需额外授权。

## 改谱影响对照

想确认一次修改对实际演奏的影响？把当前**有效**谱面设为基准，改完后一键对照两版差异。

1. **设为基准**：点击对照栏的“将当前谱面设为基准”。前端先用现有规则校验当前小节，通过后保存**录入行快照**作为基准；再次设置即覆盖旧基准（校验失败则保留旧基准并显示错误）。
2. **修改小节**：任意增删小节、改拍数 / BPM / 反复记号。
3. **发起对照**：两版在服务端分别重新校验并展开。**任一版本无效时只显示该版错误、不展示过期差异**；当前版的错误行会在录入表中标红、可点击定位。

对照规则：

- 对两条演奏带按**来源小节编号**求最长公共子序列（LCS）：同一小节被反复演奏出的多次访问**逐次参与配对**；最优解不唯一时，取“配对序号对序列”**字典序最小**的一组（逐对比较，每对先比基准下标、再比当前下标）。
- 未配对访问标为**新增**（当前版）或**删去**（基准版）；配对访问比较**拍数、BPM、遍次路径**（逐层的遍次 / 总遍数 / 是否尾部房子）。
- 两版分别按**每拍 60/BPM 秒**累计起拍时间：配对访问显示**时间偏移**（当前起拍 − 基准起拍），并单独标出**按对齐顺序的首次差异**。

结果区包含统计行、首次差异摘要、可点击的**差异列表**，以及上下两排的**对齐视图**（上排基准、下排当前；绿＝新增、红＝删去、黄＝配对有变更、红框＝首次差异）。点击差异条目或对齐列会闪烁对应的对齐列；涉及当前版的差异同时定位到录入表中的来源行。谱面再次改动后，旧对照结果会隐藏并提示重新对照。节拍器与演奏带不受对照影响，可照常使用。

`POST /api/compare` 请求体为两个小节数组：

```jsonc
{
  "baseline": [ /* 基准小节数组（录入行快照） */ ],
  "current":  [ /* 当前小节数组 */ ]
}
```

- 成功：`200`，`{"ok": true, "result": {...}}`。`result.events` 为对齐事件序列（`kind` 为 `pair` / `added` / `removed`；配对事件带 `changes`（`beats` / `tempo` / `path` 子集）与 `time_offset`），另有 `stats`、`first_difference` 与两版各自的 `visit_count` / `total_beats` / `total_seconds`。
- 任一版本校验失败：`422`，`{"ok": false, "baseline_errors": [...], "current_errors": [...]}`——无效一侧给出错误列表，另一侧为空数组。
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）；缺少 `baseline` / `current`：`400`（`INVALID_REQUEST`）。

## 反复次数反求

已知实际演奏顺序，反推各反复段该奏几遍？在录入表勾选待求位置、填入目标序列即可。

1. **勾选待求位置**：在录入表“待求”列勾选 **1～8 个带左反复的小节**（无左反复的小节复选框不可用；取消左反复会自动取消待求勾选）。面板头部实时显示已勾选的待求位置。
2. **输入目标序列**：把完整的目标演奏编号序列粘贴到文本框——以**逗号（中英文均可）或换行**分隔，最多 **512** 项，每项必须是谱面中的小节编号。
3. **开始反求**：先按现有规则校验**录入谱面**（次数照录入值，含展开与 512 上限）与**目标编号**；任一不合法即分组列出错误（谱面错误可点击定位到行），不产生方案。
4. **查看方案**：保持小节顺序、反复边界、替代结尾、拍数与 BPM 不变，其余反复的次数照录入值，枚举待求位置各取 **2～4** 的全部组合；**每个组合都须通过现有校验和展开**，超过 512 次访问的组合不计入。展开编号序列与目标完全一致的组合即为方案。
5. **写回表格**：方案按待求位置的录入行顺序组成次数元组，**字典序前 10 个**显示为可点击条目（同时给出总解数与组合空间）；点击即把该方案的次数写回表格——旧演奏带、节拍器计划与改谱对照立即失效，需重新展开或对照后才显示新结果。谱面、待求位置或目标序列再次改动后，旧反求结果会隐藏并提示重新反求。

谱面与目标均合法但没有任何组合匹配时，会明确提示**无解**（并给出已枚举的组合总数）。

`POST /api/solve` 请求体：

```jsonc
{
  "measures": [ /* 小节数组（同 /api/expand） */ ],
  "unknowns": [1, 4],              // 待求位置的 0 基行号，1~8 个
  "target": ["前奏", "A", "B"]     // 目标演奏编号序列，1~512 项
}
```

- 成功：`200`，`{"ok": true, "result": {...}}`。`result.unknowns` 为按录入行顺序排列的待求位置（`index` + `measure`），`solutions` 为字典序前 10 个方案（`times` 与 `unknowns` 一一对应），另有 `solution_count`（总解数）、`combination_count`（组合空间）与 `target_count`。
- 校验失败：`422`，`{"ok": false, "score_errors": [...], "unknown_errors": [...], "target_errors": [...]}`——三组错误分别对应录入谱面（现有规则）、待求位置与目标序列，可为空数组。
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）；缺少 `measures` / `unknowns` / `target`：`400`（`INVALID_REQUEST`）。
- 待求位置错误码：`UNKNOWN_COUNT`（非 1~8 个）、`UNKNOWN_NOT_LEFT_REPEAT`（无左反复）、`UNKNOWN_RANGE`（行号越界）、`UNKNOWN_DUPLICATE`（重复）、`UNKNOWN_FORMAT`（格式）。
- 目标序列错误码：`TARGET_EMPTY`（空序列）、`TARGET_TOO_MANY`（超过 512 项）、`TARGET_ITEM_FORMAT`（空项或超过 16 字符）、`TARGET_UNKNOWN_MEASURE`（不是谱面中的小节编号）。

## 右反复终点纠错

谱面因为右反复终点 `:|` 标错（漏标、多标、标错行）而展不开？在“右反复终点纠错”面板一键找回能展开的右标记组合。

1. **开始纠错**：点击面板右上角“开始纠错”。后端**先复用现有行级校验**（编号、拍数、BPM、次数等）：行级不通过时直接列出错误并定位到行，不进入搜索；行级通过后，原谱再走一遍**现有完整校验与展开**（含 512 次访问上限）。
2. **无需纠错**：原谱能正常展开时，直接提示“原谱已通过现有完整校验并正常展开（N 次访问），无需纠错”，不产生方案。
3. **搜索方案**：否则保持小节顺序、编号、拍数、BPM、**左反复及次数**、替代结尾遍次全部不变，**只允许切换各行的右反复终点**，在**最多 4 处切换**内寻找通过现有完整校验、且展开访问数不超过 **512** 的谱面。搜索按反复配对状态与改动预算剪枝，不遍历 64 行的全部 2^64 种组合：DFS 逐行增量维护与括号配对器一致的栈 / 尾部房子状态机，配对错误（多出的终点、主终点落在 {2+ 房子、房子未闭合、volta 无承载反复 / 遍次越界）与缺房子一旦发生即剪枝；同时精确累计访问数，超过 512 立即剪枝，只有通过这些预检的候选才跑完整 `expand()` 复核。
4. **查看方案**：只显示**切换数最少**的前 **5** 个方案；同一切换数的方案按**改动行号序列字典序**排列（更靠前行的方案排前）。每个条目列出切换数、展开后的访问数，以及逐个终点的改动（如“新增 第 4 行（C）的 :|”“删除 第 7 行（D）的 :|”）。
5. **写回表格**：点击方案**只写回各行的右反复标记**，编号 / 拍数 / BPM / 左反复 / 次数 / 替代结尾均不改动；写回后**旧演奏带、节拍器计划、改谱对照与反求结果立即失效**，需重新展开 / 对照 / 反求后才显示新结果。谱面再次改动后，旧纠错结果会隐藏并提示重新纠错。

4 处切换内找不到合法谱面（或合法但访问数均超过 512）时，会明确提示**无方案**。

`POST /api/fix-right` 请求体：

```jsonc
{
  "measures": [ /* 小节数组（同 /api/expand） */ ]
}
```

- 成功：`200`，`{"ok": true, "result": {...}}`：
  - 原谱合法：`already_valid: true`，带 `visit_count`，`solutions` 为空数组；
  - 原谱不合法：`already_valid: false`，`minimal_toggles` 为最少切换数（无方案时为 0），`solutions` 为该切换数下字典序前 5 个方案。每个方案含 `toggles`、`changes`（每项 `index` / `measure` / `action`，`action` 为 `"add"` 新增终点或 `"remove"` 删除终点）与 `visit_count`（展开访问数，≤512）；另有 `solution_count`、`expanded_candidates`（实际跑过完整展开的候选数）、`max_toggles = 4`、`max_visits = 512`。
- 行级校验失败：`422`，`{"ok": false, "score_errors": [...]}`（错误结构同 `/api/expand`，可定位到行）。
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）；缺少 `measures`：`400`（`INVALID_REQUEST`）。

## 排练记录定位

排练时随手记下的小节编号可能有误记、多记、漏记？展开成功后，把**完整排练记录**交给“排练记录定位”，它会在整条演奏带里找出与记录**编辑距离**不超过容错数的所有连续区间，帮你确定当时排到了哪一段（哪一遍）。

1. **先展开谱面**：定位只在当前成功展开的演奏带上进行；谱面未展开或计划已失效时按钮提示先展开。
2. **填写记录**：把排练记录按顺序填入文本框——以**逗号（中英文 `,` `，`、顿号 `、` 均可）或换行**分隔，**1～64** 个编号；**允许出现谱面之外的误记编号**（如把 `B` 记成了 `X`，否则误记无法体现为替换）。
3. **设置容错数**：**0～4** 的整数，即允许的最小编辑距离上限。
4. **开始定位**：后端先复用现有完整校验与展开，随后把记录（模式 P）与演奏带 T 的**任意非空连续区间** `T[s:b]` 做半全局编辑距离匹配：
   - **相同（match）计 0；错记替换（substitute）、多记删除（delete，记录里多写的项）、漏记补入（insert，区间内演奏了却没记的访问）各计 1**；
   - **区间外不计费**：记录可从任意一次访问免费开始（前面的访问不算补入），也可结束于任意一次访问（后面的访问不计）。
5. **查看结果**：列出**距离 ≤ 容错数的全部命中区间**，按 **距离 → 起点 → 终点** 升序，显示前 **10** 项并给出**区间总数**；同一遍次内的编号、以及**不同遍次的同编号区间分别计数**（每次访问各有独立的全局序号）。每个结果项展示：
   - **起止访问序号**（1 基全局序号）与区间访问数；
   - 起点 / 终点各自的**遍次路径**（如 `1/2 › 2/2`，尾部房子带“尾”）；
   - **逐项对齐**：相同（绿）/ 替换（红）/ 补入（蓝）/ 删除（黄），删除项只显示记录编号、补入项只显示区间访问；回溯从末端进行，遇到并列代价时固定按**匹配 → 替换 → 删除 → 补入**的优先级选边，对齐结果唯一。
6. **点击高亮**：点击任一结果项即在演奏带上**高亮对应访问区间**（玫红描边并滚动到起点），再次点击取消；高亮只影响显示，**不改动谱面**，也不影响节拍器与双向高亮。
7. **无结果提示**：没有任何区间满足容错数时，明确提示“无匹配区间”，并建议增大容错数或核对记录。
8. **失效与迟到响应**：**谱面、记录或容错数改变后旧结果立即清除**；同一份谱面重新展开时保留已选区间高亮。请求带自增序号，**迟到的响应不会覆盖新输入产生的结果**。

搜索**复用动态规划状态**：一次构建一张 `(记录长+1) × (访问数+1) × (容错+1)` 的来源位掩码 DP 表（记录可从任意列免费开始），全部区间的命中枚举与逐项回溯都读这一张表，**不对每个区间重算整张表**；512 次访问、64 项记录、容错 4 的最坏规模也在数十毫秒内完成。

`POST /api/locate` 请求体：

```jsonc
{
  "measures": [ /* 小节数组（同 /api/expand） */ ],
  "record": "A, B, X, C\nA,B,C",   // 排练记录文本：逗号或换行分隔，1~64 项
  "tolerance": 1                   // 容错数，0~4 的整数
}
```

- 成功：`200`，`{"ok": true, "result": {...}}`：
  - `record` / `record_count`：解析后的记录项与数量；`tolerance`、`visit_count`、`max_tolerance = 4`、`max_visits = 512`；
  - `match_count`：命中区间总数；`shown_count`：实际返回条数（≤10）；
  - `matches`：按 `(distance, start, end)` 升序的前 10 项。每项含 `distance`、`start` / `end`（1 基全局访问序号）、`interval_length`、`start_path` / `end_path`（遍次路径）、`start_visit` / `end_visit`（精简访问引用）与 `alignment`（逐项对齐：`op` 为 `"match"` / `"substitute"` / `"delete"` / `"insert"`，删除项 `visit` 为 `null`、补入项 `record_item` 与 `record_pos` 为 `null`）。
- 校验失败：`422`，`{"ok": false, "score_errors": [...], "record_errors": [...], "tolerance_errors": [...]}`——三组错误分别对应录入谱面（现有规则）、排练记录与容错数，可为空数组。
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）；缺少 `measures` / `record` / `tolerance`：`400`（`INVALID_REQUEST`）。
- 记录错误码：`LOCATE_RECORD_FORMAT`（不是字符串）、`LOCATE_RECORD_COUNT`（非 1~64 项）、`LOCATE_RECORD_ITEM_FORMAT`（某项超过 16 字符）。
- 容错错误码：`LOCATE_TOLERANCE_FORMAT`（不是 0~4 的整数）。

```jsonc
// alignment 项示例（错记 B→X：替换）
{
  "op": "substitute",            // match | substitute | delete | insert
  "record_pos": 2,               // 该项在记录中的 1 基序号（补入时为 null）
  "record_item": "X",            // 记录编号（补入时为 null）
  "visit": { "global_index": 3, "source_index": 1,
             "source_measure": "B", "path": [ /* 遍次路径 */ ] }
                                 // 删除（多记）时 visit 为 null
}
```

## 遍次排练提示单

排练时想在**某一遍的某一拍**看到提示（“第二遍这里换气”“进二房子前注意”）？展开演奏带后，在“遍次排练提示单”面板录入提示，后端按每次演奏访问的**完整遍次路径**把提示命中到具体访问的具体拍，生成按时间排列的提示单。

1. **先展开谱面**：提示单只在当前成功展开的演奏带上生成；谱面未展开或计划已失效时按钮提示先展开。
2. **录入提示**：点“＋ 添加提示”录入 **1～32 条**，每条包含：
   - **来源小节**：谱面中的小节编号（输入框带候选）；
   - **拍序**：从 **1** 开始的节内拍序；
   - **提示语**：**1～80** 字；
   - **遍次限定**（可选）：点“＋ 限定遍次”按**反复起点**限定一层或多层遍次——每条限定选一个反复起点（带左反复 `|:` 的小节行）与一个遍次；可添加多条限定不同层级，**未限定的层级匹配任意遍**。
3. **生成提示单**：后端**先复用现有完整校验与展开**（含 512 次访问上限），再逐条校验提示：**拍序不得超过该小节拍数**；**所选反复须至少出现在该小节的一条访问路径中**；**遍次须在 1～该层次数之间**；来源小节与全部遍次限定的**组合没有命中任何访问时按提示行报错**（错误列表可点击定位到对应提示卡片）。
4. **匹配规则**：按每次访问的**完整遍次路径**匹配——反复主终点之后**尾部房子的路径同样参与**（尾部房子小节也能按“该反复第 N 遍”命中）；**外层重入后内层遍次重新计算**，因此“外层第 2 遍里的内层第 1 遍”与“外层第 1 遍里的内层第 1 遍”是不同命中。
5. **查看提示单**：每条命中提示落到对应访问的指定拍，**按此前访问的拍数与生效 BPM 累计秒数**（每拍 60/BPM 秒），结果**依时间与录入顺序**列出——时间相同按录入先后。每个条目显示秒数、访问序号、来源小节、拍序、遍次路径与提示语。
6. **点击定位**：点击任一条目即在演奏带中**定位到那次访问**（与点击卡片一致的暂停定位，停在强拍并滚动到卡片）；定位只影响播放位置，不改动谱面与提示。
7. **失效与迟到响应**：**谱面或提示改变后旧单立即清除**（同一份谱面重新展开且内容未变时旧单保留）；请求带自增序号，**迟到的响应不会覆盖新输入产生的结果**。

`POST /api/cues` 请求体：

```jsonc
{
  "measures": [ /* 小节数组（同 /api/expand） */ ],
  "cues": [
    {
      "measure": "B",            // 来源小节编号
      "beat": 3,                 // 从 1 开始的节内拍序
      "text": "内层第一遍注意",   // 1~80 字
      "passes": [                // 可选：遍次限定（省略/空数组 = 不限定）
        { "open": 2, "pass": 1 } // open = 反复起点行（0 基），pass = 限定遍次
      ]
    }
  ]
}
```

- 成功：`200`，`{"ok": true, "result": {...}}`：
  - `cue_count`（提示条数）、`hit_count`（命中条目数）、`visit_count`、`total_seconds`（全长秒数）、`max_cues = 32`、`max_text_len = 80`、`max_visits = 512`；
  - `entries`：按 **(时间, 录入顺序)** 排列的命中条目。每项含 `cue_index`（来源提示 0 基序号）、`text`、`beat`、`seconds`（该拍距开演的秒数，保留 6 位小数）、`passes`（该提示的遍次限定回显）与 `visit`（精简访问引用：`global_index` / `source_index` / `source_measure` / `path`，尾部房子路径带 `tail: true`）。
- 校验失败：`422`，`{"ok": false, "score_errors": [...], "cue_errors": [...]}`——两组错误分别对应录入谱面（现有规则）与提示；提示错误按**提示行**定位（`index` 为 0 基提示序号，`measure` 为该提示的来源小节），可为空数组。
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）；缺少 `measures` / `cues`：`400`（`INVALID_REQUEST`）。
- 提示错误码：`CUES_FORMAT`（cues 不是数组）、`CUES_COUNT`（非 1~32 条）、`CUE_FORMAT`（提示不是对象）、`CUE_MEASURE_FORMAT`（编号缺失或超 16 字符）、`CUE_MEASURE_UNKNOWN`（谱面中不存在）、`CUE_BEAT_FORMAT`（拍序非 ≥1 整数）、`CUE_BEAT_RANGE`（拍序超过该小节拍数）、`CUE_TEXT`（提示语为空或超 80 字）、`CUE_PASS_FORMAT`（限定格式有误）、`CUE_PASS_DUPLICATE`（同一反复被重复限定）、`CUE_PASS_OPEN`（open 不是反复起点行）、`CUE_PASS_RANGE`（遍次超出 1~该层次数）、`CUE_PASS_REPEAT`（所选反复未出现在该小节的访问路径中）、`CUE_NO_MATCH`（条件组合没有命中任何访问）。

## 演奏片段摘谱

排练中只想要某几遍的某几段？展开演奏带后，在“演奏片段摘谱”面板按**访问序号**圈选片段，后端把选中的每次访问剪成一份**可回读的单 part MusicXML** 新谱。

1. **先展开谱面**：摘谱只在当前成功展开的演奏带上进行；谱面未展开或计划已失效时选段按钮不可用。
2. **选择片段**：点“在演奏带上选段”进入选段模式，依次点击该段的**起点与终点卡片**（再次点击同一张卡片为单访问段；可选多段，再点“退出选段”结束），或直接点“＋ 添加选段”在表格中填写起止序号。规则：**1～4 段**互不重叠、按演奏先后排列的闭区间，**合计 2～64 次访问**；同一来源小节在不同遍次的访问各有独立序号，可重复选入。选段覆盖的访问会在演奏带上高亮（仅视觉，不改动谱面）。
3. **生成摘谱**：后端**先复用现有完整校验与展开**（含 512 次访问上限），再校验选段；随后把选中的每次访问依序变成一行独立录入行：
   - **编号重排为 1 起的连续整数**（`"1"`、`"2"`……）；
   - **保留拍数**，**清除反复与房子记号**（无左右反复、无次数、无 volta）；
   - **每段首行写入该次访问的生效 BPM**——段间剪接处的速度自带，不会误沿用前一段末尾的速度；**段内其余行仅在生效 BPM 相对上一选中访问变化时写入**，否则留空沿用。
4. **导出与回读校验**：摘谱行自身先过一遍现有校验与展开，再用现有 **MusicXML 结构导出**生成单 part 文件（导出内部已含往返自检）；服务端随即用现有导入入口**回读**生成的文件，**回读演奏带的拍数与生效 BPM 必须逐行对应所选访问**，否则返回 `MUSICXML_EXCERPT_ROUNDTRIP`、**不产生下载内容**。
5. **预览与下载**：预览表逐行列出**新编号、所属段、拍数、生效 BPM（标注“写入 / 沿用”）、原访问序号、来源编号与遍次路径**，段首行有分隔线；确认后点“下载 MusicXML”得到 `.musicxml` 文件（可用“导入 MusicXML”重新打开，展开后即为所选片段的演奏顺序）。**原谱与演奏带不受影响**。
6. **失效与迟到响应**：**谱面或选段变化后旧预览立即清除**（同一份谱面重新展开且内容未变时旧预览保留）；请求带自增序号，**迟到的响应不会恢复已过期的预览**。

`POST /api/excerpt` 请求体：

```jsonc
{
  "measures": [ /* 小节数组（同 /api/expand） */ ],
  "segments": [
    { "start": 2, "end": 4 },   // 1 基全局访问序号闭区间，start ≤ end
    { "start": 9, "end": 11 }   // 1~4 段，互不重叠且按演奏先后排列，合计 2~64 次访问
  ]
}
```

- 成功：`200`，`{"ok": true, "result": {...}}`：
  - `segment_count` / `visit_count` / `total_beats`：段数、选中访问总数与总拍数；`max_segments = 4`、`max_excerpt_visits = 64`、`max_visits = 512`；
  - `segments`：各段回显（`segment` / `start` / `end` / `visit_count` / `first_row`——该段首行的新编号）；
  - `rows`：摘谱录入行（编号 1 起连续整数、保留拍数、无反复与房子记号；`tempo` 仅段首与段内速度变化处非空）；
  - `mapping`：逐行映射（`row` 新编号、`segment` 所属段、`visit` 原访问引用——`global_index` / `source_index` / `source_measure` / `beats` / `tempo`（生效 BPM）/ `path` 遍次路径）；
  - `musicxml`：可回读的单 part MusicXML 文本。
- 校验失败：`422`，`{"ok": false, "score_errors": [...], "segment_errors": [...], "excerpt_errors": [...]}`——三组错误分别对应录入谱面（现有规则）、选段与摘谱生成（含回读校验），可为空数组；选段错误按段（0 基）定位。
- 请求体不是合法 JSON：`400`（`INVALID_JSON`）；缺少 `measures` / `segments`：`400`（`INVALID_REQUEST`）。
- 选段错误码：`EXCERPT_SEGMENTS_FORMAT`（segments 不是数组）、`EXCERPT_SEGMENT_COUNT`（非 1~4 段）、`EXCERPT_SEGMENT_FORMAT`（段形状或 start/end 有误）、`EXCERPT_SEGMENT_RANGE`（超出 1~访问总数）、`EXCERPT_SEGMENT_ORDER`（重叠或未按演奏先后排列）、`EXCERPT_VISIT_COUNT`（合计非 2~64 次访问）；回读校验不通过为 `MUSICXML_EXCERPT_ROUNDTRIP`。

- 速度问题：错误码 `TEMPO_FIRST_REQUIRED`（首节缺失）/ `TEMPO_RANGE`（非整数或超出 40～240）

## 实现要点

展开器是一个单遍栈式解释器：

1. **行校验**：编号唯一、拍数/次数/遍次范围、次数必须与左起点同时出现。
2. **括号配对**：用栈把右终点匹配给最近未闭合的左起点；交叉括号会留下未闭合起点而被拒绝。主终点位于 `{1` 房子时，配对状态机继续按“期待房子编号 2、3、…”识别尾部房子（可带次级终点、可跨小节），编号不符或遇到普通小节即结束，因此内层尾巴之后的外层房子不会被误吞。同一行可带“同线双终点”（`right_closes`，仅 MusicXML 导入产生）：该行先按房子状态机消费一个内层次级终点（不弹栈），再弹栈闭合外层反复，归属与栈不一致报 `REPEAT_CLOSE_OWNER`。
3. **volta 归属**：每个小节静态归属于包含它（或作为尾部房子紧随其后）的最内层反复；遍次超出该反复 `times` 即报错。
4. **展开**：维护反复栈帧 `[repeat_id, pass]`。左起点入栈（跳回复执行时复用栈顶帧）；volta 小节按栈顶帧遍次决定是否演奏；右终点按遍次递增并跳回，或在最终遍出栈。**同线双终点行**先处理内层房子终点（本行 volta 属于它），内层非最终遍跳回时把外层主终点**延后**（记录该边界），等内层最终遍再次到达、内层出栈后外层成为栈顶才在同一道边界闭合外层；无房子的两个同线主 backward 同理。外层重新进入时内层是新栈帧，遍数自然从 1 开始。速度按来源小节表解析一次（首节必填、留空沿用），每次产生访问时直接附带其来源小节的生效速度，因此反复路径天然得到正确 BPM。
5. 每次产生访问前检查总数，达到 **512** 即中止并返回 `TOO_MANY_VISITS`。

### 改谱对照

`app/diff.py` 接收两版展开结果：先按来源小节编号对两条访问序列求 LCS——后缀 DP 求长度，再贪心回取，每步取可行的最小基准下标、再取最小当前下标，保证“配对序号对序列”字典序最小；未配对访问即新增 / 删去，同一缺口内删去排在新增之前。配对访问比较拍数、BPM 与归一化遍次路径（逐层 遍次/总遍数/是否尾部房子；反复 id 两版各自编号、跨版无意义，不参与比较）。起拍时间按每拍 60/BPM 秒在两版各自累计，配对访问输出时间偏移，并按对齐顺序记录首个差异事件。

### 反复次数反求

`app/solve.py` 复用同一引擎：先用录入值（含待求位置的占位次数）完整校验并展开录入谱面，再校验待求位置（1~8 个、必须带左反复）与目标编号序列（1~512 项、必须是谱面编号）。随后按 `itertools.product(2~4)` 枚举次数组合——枚举顺序即元组字典序，方案天然有序；每个组合都重新走 `expand()` 的完整校验与展开，校验失败（如缺替代结尾房子）或超过 512 次访问的组合直接跳过。展开是确定性的，`expand()` 的可选 `expect` 参数在访问编号与目标不符、或访问数超出目标长度时提前中止（`EXPECT_MISMATCH`），与完整展开后比对结论一致，仅作剪枝：8 个待求位置的最坏情况（6561 个组合）也能在约 2 秒内完成。展开编号序列与目标完全一致的组合计入方案，最多返回字典序前 10 个并给出总解数。前端把方案次数写回表格后走与手动编辑相同的失效路径（`invalidatePlan`）：旧演奏带变灰、节拍器计划作废、对照结果隐藏，重新展开或对照后才显示新结果。

### 右反复终点纠错

`app/rightfix.py` 先跑行级校验（`normalize_rows`），原谱再走完整 `expand()`：合法即返回 `already_valid`。否则按切换数 k = 1…4 逐层 DFS，每行先尝试“切换右标记”再尝试“保留”，使方案天然按改动行号序列字典序产出，每层取前 5 个即止。DFS 逐行增量维护一份与 `_match_brackets` 同构的配对状态（起点栈、已闭合帧、尾部房子“期待编号”状态机、栈内 times 乘积与已确定访问数），凭快照回滚，按两类依据剪枝：

- **改动预算**：剩余行数放不下剩余切换数时剪枝；当前栈中起点数加后缀左起点数超过剩余行数（没有足够的行容纳必需右终点）时剪枝。
- **反复配对状态 + 访问数**：多出的右终点、主终点落在 {2+ 房子、房子未闭合 / 缺失、volta 无承载反复或遍次越界，一旦发生即不可能被后续切换修复，立即剪枝；同时精确累计每行的访问数（非 volta 小节按嵌套栈各层 times 连乘，volta 房子小节在所属反复上只奏一次），累计超过 512 立即剪枝。

只有通过全部增量预检的候选才在叶子上跑同一套完整 `expand()` 复核（展开步数、512 中止等规则全部复用），因此深嵌套、64 行的最坏结构也只会对极少数候选做完整展开。前端点击方案只写回各行 `right_repeat`，随后走与手动编辑相同的失效路径（`invalidatePlan` + 反求 / 纠错结果收起）。

### MusicXML 结构导入

`app/musicxml_import.py` 用标准库 `xml.etree.ElementTree` 解析（先递归去除命名空间前缀），只读取结构、忽略一切音符内容：

1. **形状校验**：根元素必须是 `score-partwise`（`score-timewise` 给出专门提示），`part-list` 声明数与实际 `<part>` 数都必须恰为 1，小节数 2～64，`<measure number>` 作为行编号。
2. **逐小节拍号 / BPM**：`<time>` 只接收单一 `beats` + `beat-type=4`（拒绝 `senza-misura` 与混合拍号），首节必有、后续沿用；BPM 只看首个 `<note>` 之前的 `<sound tempo>` 与四分音符单位 `<metronome><per-minute>`（附点单位与非整数拒绝），首节必有、后续留空。
3. **记号事件化**：把每个 barline 的 `<ending>` / `<repeat>` 映射到“小节间边界 + side（left/right）+ 文档序号”，同一物理小节线上右 barline 先于左 barline、同 barline 内保持文档顺序；配对只认**物理边界**——某小节的右 barline 与下一小节的左 barline 是同一道线，记号写在哪一侧不影响配对。房子覆盖：右 barline 上的 `start` 从**下一小节**起覆盖（所在小节属线另一侧的公共段，不会被误标），左 barline 上的 `start` 从所在小节起覆盖；同线特例先做一次 forward/backward 的 LIFO 预配对（次级终点不弹栈），只有右 barline 的编号 1 `start` **自身也在该边界闭合**（`stop`/`discontinue` 在该线任一侧，或下一遍房子在另一侧开始形成隐式闭合）、且同线上存在一个闭合的恰是“start 处理前栈顶 forward”的主 backward 时，才按规范把线前小节计入第一房子；嵌套反复里内层 backward 与更外层 `{1 start` 共线时，内层 backward 闭合的是更内层 forward、不满足归属，内层终点留在**线前小节**、外层第一房子从**线后小节**覆盖、外层终点落在房子末节。闭合记号（无论写在哪一侧）都以所在边界为最后一个覆盖小节。两遍扫描：先 `start → stop/discontinue` 配对房子（允许同一线另一侧的下一房子隐式闭合，要求单个 1～4 编号），再逐小节按“左 barline → 右 barline”驱动 forward/backward 的 LIFO 栈——与编号 2+ 房子闭合同 barline 的 backward 识别为次级终点（不弹栈，但登记归属）；跨侧时另一侧没有自己的 backward 也按物理边界认作次级，但同线两侧各有一个 backward（嵌套）时各认本侧闭合记号，外层 backward 不被对侧内层房子误吞；主终点一律落在 backward 所在边界前的小节（真正同线闭合下该小节正是第一房子覆盖的唯一小节）；`times` 缺省 2、限 2～4，写到起点行。**同一物理边界两侧各有一个 backward（一侧内层次级、一侧外层主终点）时，终点行同时登记两个反复起点行**：单行单终点只写布尔右标记（`right_closes` 留空），双终点行额外写 `right_closes = [内层起点行, 外层起点行]`，交给展开引擎在该边界先完成内层房子、再闭合外层反复；次级 backward 的承载反复优先取“栈或已配对中起点行最大（最内层）”的一个，避免误认外层 forward。
4. **复用现有引擎**：转换出的录入行直接调用 `expand()` 跑完整校验与展开（含 512 上限），任何不通过都按源行 / 源小节返回，不产生结果。前端只在用户确认后替换表格，并走与“载入示例”相同的全量失效路径（演奏带、节拍器计划、对照、反求、纠错结果全部收起）。

### MusicXML 小节时值审计

`app/musicxml_audit.py` 复用导入端的 XML 基础与拍号解析（`_parse_time`），文件范围检查（`score-partwise`、单 part、小节数、分母为 4 的拍号首节必有）与结构导入完全一致；速度、反复、房子等记号不参与审计。每个小节内按文档顺序扫描：`attributes/divisions` 更新生效值（正整数校验，跨小节沿用，本小节出错后仍照常更新以保证后续小节的沿用判断）；`note` / `backup` / `forward` 驱动全小节唯一的游标（`fractions.Fraction`，拍 = 四分音符）。普通音符与休止符从游标起占用 `[start, start+duration/divisions)` 并推进游标；`<chord/>` 继承前一同声部普通音符的起点、不推进游标，同起点和弦合并为一个区间（终点取组内最大）；`<grace/>` 整体跳过；`<backup>` 回拨游标，变负即硬错误；`<voice>` 缺省 `1`。缺少 divisions、非法 duration、负拍位、孤立 chord 均为硬错误——每节只报第一个、按源小节定位，不显示通过。无硬错误的小节按声部汇总区间：排序后相邻区间起点落在此前最大终点之内即**非和弦重叠**，`[0, 拍数)` 内未被覆盖的部分即**缺拍**，终点超出拍数即**越过小节边界**；全小节无非 grace 音符时按默认声部整节缺拍。问题按（小节、声部、拍位）升序输出，拍位以 `p/q` 文本表示。前端审计与结构导入共用同一个文件选择：结果只渲染在导入面板内、绝不触碰录入表格，换文件或关闭面板即清除并作废在途请求（自增序号），迟到响应直接丢弃。

### MusicXML 结构导出

`app/musicxml_export.py` 复用同一引擎做**反向**转换，并用导入器做往返自检：

1. **先 `expand()`**：谱面非法时直接返回现有错误（按原始行定位），不产生文件；合法则取 `normalize_rows()` 的规整行，并调用与展开器内部同构的 `_match_brackets()` / `_assign_volta_owners()` 得到配对与 volta 归属。
2. **barline 布置**：forward 放起点小节左 barline；每个反复的主 backward 放 `times`、次级 backward 不放；同 (所属反复, 遍次) 的连续 volta 小节合并为一个房子（首小节左 barline `start`、末小节右 barline `stop`，右线 stop 与 backward 同 barline 时 stop 在前）。**同线双终点**行的内层 backward 放本小节右 barline、外层主 backward 移到下一小节左 barline（同一物理线两侧）；若下一小节同时是左反复起点，则该小节开头写两道左 barline——外层主 backward 独占第一道（先闭合旧反复），房子 start 与新 forward 同处第二道（后开启新反复），保证重新导入时配对不错位；仅当双终点行已是最后一个小节（外层 backward 无处安放）时才返回 `MUSICXML_EXPORT_BARLINE`。
3. **逐行生成**：每小节显式写分母为 4 的拍号（`divisions=1`）、仅标记行写 `<sound tempo>`、全小节休止符 `<rest/>`（时长 = 拍数）；编号做 XML 转义。
4. **往返自检**：生成的文本立即交给 `import_musicxml()` 重新导入，逐字段比较归一化行（编号 / 拍数 / BPM / 左右反复 / `right_closes` / 次数 / volta）并整体比较展开结果（来源编号、遍次路径含尾部标记、生效 BPM、配对摘要、总拍数、访问数）；任一不一致都不产生文件。因此**能下载的文件必然可被现有入口还原成同一条演奏带**，导出过程不修改任何表格字段或已有结果。

### 排练记录定位

`app/locate.py` 复用 `expand()` 先把谱面完整校验并展开，演奏带每次访问取来源小节编号作为文本 T；记录文本按逗号 / 换行（`,` `，` `、` 与 CR/LF）切分，去空白段后限 1～64 项、每项 ≤16 字符，**不校验编号归属**（误记必须能保留），容错数限 0～4 整数。

匹配是**半全局 Levenshtein**：相同 0、替换 / 删除 / 补入各 1，区间外免费（任意起点开始、任意终点结束）。为避免“每个区间重算一张表”，只建一张**来源位掩码累积 DP 表**：表 `R[i][j][c]` 是一个整数，第 s 位为 1 当且仅当存在从 `(0,s)`（记录第 0 项、演奏带第 s 次访问）到 `(i,j)`、代价 ≤ c 的路径。第 0 行每列都可免费开新区间（置位 j），并允许从左邻以代价 1 一路补入；其后每格按 匹配/替换（对角，编号相同代价 0、否则 1）、删除（上方，代价 1）、补入（左方，代价 1）做位掩码的移位与按位或——所有起点的状态在同一张表里并行传播。命中枚举只扫末行：第 tolerance 层里出现的每个来源位 s（且 s < 终点 b，排除空区间）对应一个命中区间，其精确距离是该位出现的最低层；按 `(距离, 起点, 终点)` 排序取前 10 并给出总数，不同遍次的访问天然占据不同来源位、分别计数。

逐项对齐**回溯同一张表**：精确代价层由 `E[i][j][c] = R[i][j][c] & ~R[i][j][c-1]` 即时导出，从 `(m,b)` 逆向检查来源位 s 是否落在对应前驱层，并列代价时固定按**匹配 → 替换 → 删除 → 补入**选边；删除项只带记录编号、补入项只带区间访问引用。前端按自增请求序号丢弃迟到响应，谱面 / 记录 / 容错任一变化即清除旧结果与演奏带高亮（同谱重展保留已选高亮），点击结果只给区间卡片加视觉高亮类，不写回任何谱面字段。

### 遍次排练提示单

`app/cues.py` 复用 `expand()` 先把谱面完整校验并展开，随后对 1~32 条提示做两层校验：**形状校验**（条数、编号 / 拍序 / 提示语格式、限定结构）不依赖谱面；**语义校验**在展开结果上进行——拍序不得超过该小节拍数、每个遍次限定的反复（按起点行定位）须出现在该小节的访问路径中且遍次在 1~该层次数之间。形状有误的提示行跳过语义检查，其余行照常，全部错误按提示行汇总（`index` 为 0 基提示序号）。

匹配直接读取每次访问的**完整遍次路径**（展开器已保证：尾部房子在路径末尾带 `tail` 标记、外层重入时内层栈帧重新打开即遍次从 1 重计）：提示命中一次访问，当且仅当来源小节相同且每条限定 `(反复, 遍次)` 都能在该访问路径中找到同层同遍的条目；未限定的层级不参与比较。组合无命中按提示行报 `CUE_NO_MATCH`。计时与改谱对照同一约定：每次访问的起拍秒数由此前各访问 `拍数 × 60/BPM` 累计，命中提示的秒数 = 访问起拍 + `(拍序 − 1) × 60/该访问生效 BPM`，保留 6 位小数；提示单按 **(秒数, 提示录入序号, 访问序号)** 排序，即“依时间和录入顺序”。

前端提示编辑器与录入表联动：反复起点下拉由当前表格带左反复的行生成（谱面改动后失效的起点保留原值展示、交给服务端校验报错）；生成走与定位一致的失效路径——谱面或提示任一编辑即清除旧单（同谱重展经签名比对保留），自增请求序号保证迟到响应不恢复；点击条目复用节拍器的 `seekVisit` 暂停定位到该次访问强拍并滚动到卡片，不改动谱面。

### 演奏片段摘谱

`app/excerpt.py` 复用 `expand()` 先把谱面完整校验并展开，随后校验选段：1~4 段 `{start, end}` 闭区间（1 基全局访问序号、`start ≤ end`、不越界）、段间互不重叠且按演奏先后升序、合计 2~64 次访问。摘谱行生成只做映射、不回写输入：每次选中访问依序产生一行——编号取 1 起连续整数、拍数照抄、反复 / 房子字段全部置空；`tempo` 在每段首行无条件写入该次访问的生效 BPM（段间剪接处的速度因此自带，不依赖前段末尾的标记），段内其余行仅当生效 BPM 相对上一选中访问变化时写入，否则留空沿用——与导入端“留空沿用最近标记”的解析口径一致，回读后每次访问的生效 BPM 与所选访问逐行相同。

生成的摘谱行先再过一遍 `expand()`（防御性复核），随后交给现有的 `export_musicxml()` 生成单 part MusicXML（继承其完整校验、barline 编码与往返自检），最后用 `import_musicxml()` 回读并**逐行比对**回读演奏带与所选访问的拍数、生效 BPM；任一不一致即返回 `MUSICXML_EXCERPT_ROUNDTRIP`，不下发文件。前端选段支持“演奏带点选”（选段模式下点击卡片记起点、再点记终点，同卡两次为单访问段）与手工填号两种方式，选段覆盖的访问在演奏带上仅作视觉高亮；生成走与定位 / 提示单一致的失效路径——谱面或选段任一编辑即清除旧预览（同谱重展经签名比对保留），自增请求序号保证迟到响应不恢复；下载只读取最近一次成功结果，不改动表格、演奏带与节拍器计划。

### 前端节拍器

- **前瞻调度（lookahead scheduling）**：25 ms 轮询 + 0.12 s 音频时钟前瞻窗口，`OscillatorNode` 用 `start(when)/stop(when)` 排时间点；强拍与弱拍用不同频率/泛音/包络区分，全部本地合成。
- **游标与暂停语义**：内部游标在排队时即前移；视觉高亮由独立的 `setTimeout` 在音频时间临近时触发。暂停/停止/定位统一走 `flush()`——`stop()` 全部未响 `OscillatorNode` 并取消视觉定时器；暂停时把游标回退到队列中最早的“未响拍”，即恢复后的起点。
- **计划失效**：任何对小节、拍数、BPM 的编辑都把当前展开结果标记为 stale，立即停止音频、禁用控制条并提示重新展开；新结果通过 `transport.reset()` 装载。
